# 바람결 섬 — Unity 디자인 기록

## 중심 경험

**내가 꾸민 작은 친구와 낯선 장소를 발견하고, 새로운 친구를 데려오는 모험.** 공방과 탐험을 연결해 만든 캐릭터가 전시물에 머물지 않고 플레이의 주인공이 되도록 한다.

공방 → 파트너 선택 → 섬 탐험·수집 → 성소 전투·축복 → 수호자 영입 → 다시 탐험하는 흐름이다. 이번 Unity 버전은 네이티브 메시와 카메라를 사용하는 로컬 싱글플레이 프로토타입이다. 대규모 지형 스트리밍, 온라인 협동, 절차적 던전 배치, 실시간 액션 전투는 현재 범위에 포함하지 않는다.

## 시각 방향

손으로 빚은 듯한 둥근 캐릭터와 작은 디오라마 섬을 사용한다. 캐릭터는 배색·볼·눈의 반사점·발끝·귀의 안쪽·장식까지 메시로 구성한다. 지형은 해안 단면, 둥근 나무, 물빛 호수, 낮은 유적과 길을 통해 서로 다른 장소를 읽을 수 있게 만든다.

| 요소 | 선택과 목적 |
| --- | --- |
| 기본 팔레트 | 세이지 그린·민트·크림. 밝은 자연과 따뜻한 종이 UI의 인상을 연결한다. |
| 텍스트 | 짙은 녹색 본문과 Noto Sans KR. 영어는 작은 장 제목, 한국어는 행동과 설명에 사용한다. |
| 카메라 | 섬은 따라오는 비스듬한 시점, 공방은 친구 중심, 던전은 양쪽 참가자와 방 전체가 보이는 시점. |
| 조명 | 따뜻한 태양, 부드러운 그림자, 차가운 주변광, 옅은 안개로 형태와 깊이를 드러낸다. |
| HUD | 중앙 3D 장면을 남기고 목표·파트너·미니맵·자원을 가장자리에 놓는다. |
| 피드백 | 짧은 이동 공격, 작은 빛 조각, 합성한 벨 소리, 명시적인 행동 결과를 함께 제공한다. |
| 성소 구분 | 이끼색 숲, 테라코타 잿불, 라벤더 달빛으로 적·바닥·주변광의 테마를 맞춘다. |

외부 원작의 모델·이미지·음악을 복제하지 않는다. 환경과 캐릭터는 `Rendering` 코드, 화면은 `GameUI`에서 생성한다. Built-in Render Pipeline을 사용하고 필요한 셰이더를 빌드에 포함해 첫 실행에 외부 아트 패키지를 요구하지 않는다.

## 플레이 규칙과 회복 경로

포획은 타이밍을 맞추는 방식이다. 열매는 성공 구간을 넓히고, **편하게 수집하기**는 타이밍 입력을 생략한다. 실패한 유효 시도는 볼을 소비하므로 캠프 보충을 제공한다. 저장한 창작 캐릭터도 야생 목록에 포함해 만든 결과를 탐험에서 다시 만날 수 있다.

던전 적은 기본 공격 → 힘 모으기 → 강한 공격을 예고한다. 방어는 강한 공격을 줄이고 에너지를 모으며, 속성 기술은 자원을 소비해 높은 피해를 준다. 사용할 수 없는 기술·회복은 턴을 소비하지 않는다. 첫 두 방의 축복은 중복 선택할 수 없고, 마지막 방을 완료해야 영구 보상을 받는다. 축복 선택 창은 진행에 필수인 상태이므로 단순 닫기로 선택을 건너뛰지 않는다.

중도 귀환과 패배는 현재 원정만 끝낸다. 섬 위치와 영구 수집 기록은 던전 상태와 분리한다. 보상은 검증된 클리어에만 한 번 지급하고, 불러온 데이터는 허용 값·색상·수량 범위로 정규화한다.

## 검증의 경계

순수 C# 검사는 자원과 상태 전이를 검증한다. Unity Editor에서는 실제 메시·조명·폰트·UI 클릭·장면 전환을, Windows 플레이어에서는 저장과 실행을, WebGL에서는 로딩·브라우저 저장·입출력을 각각 확인해야 한다. 자동 스모크는 일반 플레이 저장과 다른 파일을 사용한다. 검증 결과를 남기는 파일과 실행 로그 없이 빌드·플레이 통과를 주장하지 않는다.

다음 확장 우선순위는 플레이 테스트로 정한다. 현재 구조에서는 충돌·카메라 가림 개선, 각 친구의 고유 기술, 탐험 퀘스트, 재도전 보상, 터치 입력을 독립적으로 추가할 수 있다.
