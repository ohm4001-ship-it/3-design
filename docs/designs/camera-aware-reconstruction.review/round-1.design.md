## 확인한 문제와 한계
- `src/orientation.ts`는 사진 회전을 90° 단위로, `src/reconstruct/ai-correct.ts`는 메시 방향을 Y축 회전 네 가지로 제한한다.
- `src/reconstruct/voxel-reconstruct.ts`는 모든 외곽 조건의 교집합을 취한다. `src/pipeline.ts`는 AI 메시에도 이 외곽을 적용하므로 불일치 사진이 정상 형상을 과하게 깎을 수 있다.
- `src/preprocess.ts`는 전체 외곽 중심으로 이미지를 재배치한다. 정확한 직교 뷰에서는 유효하지만, 몸통 중심 기준을 유지하려면 별도 기준점과 이미지 변환 기록이 필요하다.
- `stanley_xyz_aligned`는 AI 생성 이미지이며 안내 파일도 정확한 직교 투영과 형상 일관성을 보장하지 않는다. 서로 다른 형상은 자세 정렬만으로 일치시킬 수 없다.
- 현재 Hunyuan 연결 코드는 이름이 지정된 앞·뒤·좌·우 이미지를 받으며 카메라 자세를 전달하지 않는다. arbitrary-angle 입력을 그대로 네 슬롯에 넣어 해결됐다고 간주하지 않는다.
- 근거는 코드·사진의 정적 확인이다. 실제 생성 재실행이나 보정 전후 파손 비교는 아직 수행하지 않았다.

## 처리 흐름과 공통 데이터
사진 검사 → 초기 메시 → 카메라 정렬 → 제한된 형상 보정 → 색 투영 → 재투영 검증 → 결과 선택.

사진마다 원본 크기, 마스크, 원본↔전처리 좌표 변환, 카메라 투영 종류, 회전·이동, 배율 또는 초점거리·주점, 기준점, 잠금 상태, 정렬 오차와 신뢰도를 저장한다. 원본은 유지하고 보정값을 별도로 저장한다. EXIF 방향과 회전·크롭·리사이즈를 투영 좌표에 반영한다.

월드 좌표는 기존 +X 오른쪽, +Y 위, +Z 앞을 유지한다. 카메라 회전·이동은 월드→카메라 변환으로 정의하고 이미지 좌표는 오른쪽·아래 방향이다. 직교·원근 투영, 깊이와 가시성 판정, 색 샘플링, 검증은 하나의 투영 모듈을 사용한다. 기존 `BASES`는 직교 기본값으로 재사용한다.

정투영 참조는 기존 직교 카메라로 시작하고, 실제 사진은 원근 카메라로 시작한다. 입력 종류를 사용자가 지정할 수 있다. 초점거리가 알려져 있으면 고정하고, 알려지지 않으면 제한된 범위에서 추정한다. 같은 실제 카메라로 찍은 사진만 내부 파라미터를 공유한다. 큰 렌즈 왜곡은 보정된 입력을 요구하거나 검토 상태로 돌린다.

## 초기 형상과 정렬
- 정투영에 가까운 참조는 기존 다중 이미지 생성기를 재사용한다. 실제 사진 경로는 사용자가 선택한 기준 사진 한 장의 초기 메시 생성부터 검증한다. 현재 공급자·체크포인트가 이 요청으로 유효한 메시를 생성하는지는 구현 첫 단계에서 확인한다.
- 단일 이미지 경로가 지원되지 않으면 임의 각도 사진을 정투영 슬롯에 억지로 넣지 않는다. 사용자가 기존 초기 메시를 제공하거나 공급자 변경·재촬영을 선택하도록 생성 상태와 원인을 표시한다.
- 초기 메시를 고정한 채 슬롯 방향 주변의 후보를 비교한 뒤 연속적인 yaw·pitch·roll, 이동, 배율 또는 제한된 초점거리를 다듬는다. 외곽선 거리와 기준점 오차를 함께 사용한다. 로고·손잡이는 원통의 방향 모호성을 줄이는 보조 단서다.
- 월드 방향과 모델 크기를 고정해 카메라와 메시가 함께 돌아가거나 커지는 모호성을 막는다. 기준 사진이 정면일 필요는 없다. 기준점과 초기 메시의 월드 방향이 촬영 자세와 분리되어야 한다.
- 자세를 먼저 맞추고 형상을 조금 보정한 뒤 다시 자세를 확인한다. 후보 해가 여러 개이거나 오차가 충분히 줄지 않으면 자동 완료 대신 수동 보완으로 전환한다.

## 형상 보호와 실패 처리
- 사진별 외곽 오차, 마스크 품질, 기준점 잔차, 후보 간 모호성을 함께 평가한다. 낮은 신뢰도를 단순한 큰 잔차와 동일시하지 않는다. 잘못된 초기 형상도 잔차를 키울 수 있다.
- 모든 사진의 최소 거리로 강제 깎는 대신 신뢰도가 높은 사진을 중심으로 경계 오차 허용폭과 강건한 손실을 적용한다. 제외된 사진과 이유를 결과에 표시하며, 재정렬한 뒤 다시 포함할 수 있다.
- 충분한 방향의 믿을 수 있는 관측이 없으면 초기 형상에 대한 수정량을 줄이거나 보정을 중단한다. 보지 못한 부분을 관측된 정확한 형상으로 표시하지 않는다.
- 보정은 초기 메시 유지 항, 국소 매끄러움, 단계별 최대 변위로 제한한다. 손잡이 연결·구멍 등 지정한 보호 부위가 손상되면 해당 보정을 되돌린다. 연결 성분 수만으로 구멍 보존을 판단하지 않는다.
- 보정 결과가 보호 조건을 위반하거나 정렬 점수를 떨어뜨리면 유효한 초기/이전 메시를 표시하고 검토 필요로 알린다. 보정 전·후 GLB와 비교 이미지를 저장한다. AI 실패 시 자동 실루엣 전환은 신뢰할 수 있는 카메라·관측이 있을 때만 허용한다.
- 색 투영도 추정된 카메라와 깊이 가시성을 사용한다. 반사광·음영 차이를 형상 오류의 단독 근거로 삼지 않는다.

## 사용자 화면과 치수 옵션
- 사진별 상태: 자동 정렬 완료 / 기준점 필요 / 사진 간 불일치 / 입력 확인 필요.
- 원본 위에 재투영 외곽을 겹쳐 보여주고 각도·기준점 수정, 카메라 잠금, 사진 제외·복원을 제공한다. 기준점은 같은 물체의 대응 위치로 지정한다. Stanley에서는 몸통 축·바닥·손잡이 접점을 활용한다.
- 결과에서는 초기/보정 메시와 사진별 외곽 오차를 비교한다. 기존 정투영의 반대면 거울상 검사는 임의 각도 사진에 그대로 적용하지 않는다.
- 치수 옵션은 mm 단위로 측정 구간이나 대응 3D 지점과 실측값을 받는다. 한 치수는 전체 균일 배율만 보정한다. 여러 치수는 지정 구간 제약으로 사용하며 임의 축 늘이기로 자동 해결하지 않는다.
- 치수가 서로 모순되면 해결되지 않은 잔차를 표시한다. mm 단위 모델 파일과 단위·실측값·잔차 메타데이터를 함께 내보내고 실제 형상 정확도와 스케일 보정을 구분한다.

## 구현 순서와 검증 기준
기존 TypeScript 생성·검증 API, 스튜디오, 메시 내보내기를 확장한다. 자세 검색은 기존 CPU 렌더러를 재사용하는 제한된 후보 탐색부터 구현한다. 미분 렌더러 도입은 정확도·실행 시간 실험 결과로 결정한다. 기존 웹 화면과 CLI로 배포하고 새 서비스는 만들지 않는다.

| 단계 | 구현과 통과 기준 |
|---|---|
| 1. 공통 투영 | 직교·원근·이미지 변환·깊이 가시성의 수학 테스트. 기존 직교 기준점 투영 차이 0.5픽셀 이하를 목표로 한다. 실제 사진용 초기 메시 경로의 지원 여부도 확인한다. |
| 2. 자동·수동 정렬 | 비대칭 몸통+손잡이 테스트 메시를 실제 카메라에서 렌더링한다. yaw·pitch·roll 각각 ±5/10/15° 오차로 초기화해 복구를 평가한다. 이미지 평면 회전만으로 입체 촬영각 시험을 대체하지 않는다. |
| 3. 안정적인 보정 | 정상 입력과 의도적으로 어긋난 사진 한 장을 비교한다. 보호한 손잡이 연결·구멍을 유지하거나 보정을 거부해야 한다. 모든 사진이 모순될 때도 정상 완료로 표시하지 않는다. |
| 4. 색·화면 통합 | 동일한 카메라 투영으로 로고 위치와 가시성, 제외 사진 안내, 초기/보정 비교가 일치하는지 확인한다. |
| 5. 치수 옵션 | 한 치수의 균일 스케일, 여러 치수의 모순, 단위 내보내기를 검증한다. mm 단위 임의 정확도 보장은 하지 않는다. |

정렬 초기 목표는 비대칭 합성 테스트의 관측 가능한 회전 오차 3° 이하와 각 뷰 실루엣 IoU 0.90 이상이다. 대칭으로 관측 불가능한 회전은 각도 통과 대신 모호성 안내를 요구한다. 이 수치는 아직 달성된 성능이 아니다. 실제 사진의 통과 기준과 시간 제한은 별도의 촬영 검증 세트에서 정하고 결과와 함께 공개한다. 기존 Stanley AI 참조는 안전성·불일치 안내 시험에 쓰며 실측 정확도의 정답으로 사용하지 않는다.

## 미해결 사항
- 실제 사진의 초기 메시 품질과 공급자 단일 사진 지원은 실행 검증이 필요하다.
- 실제 사진의 촬영 거리·렌즈 정보·각도 오차 범위·목표 처리 시간은 아직 제공되지 않았다.
- 치수 옵션의 허용 오차는 사용 목적과 실측 데이터가 있어야 결정할 수 있다.

## The Assignment
같은 Stanley의 몸통 높이·지름·손잡이 포함 폭을 재고, 카메라를 고정한 사진 5장을 별도 검증 세트로 준비한다. 정면 기준과 촬영 방향을 기록하고, 기울어진 사진도 추가한다. 실제 촬영 데이터가 준비되기 전에는 합성 카메라 테스트로 개발 검증을 시작한다.

## 대화에서 확인한 판단
- “1,2번을 메인 기능으로, 3번을 옵션으로 제공”: 즉시 쓸 수 있는 안정성과 실측 요구를 다른 기능 수준으로 구분했다.
- “공통 카메라 엔진 + 자동 정렬 + 수동 보완”을 선택했다. 자동 추정이 불확실한 사진을 사용자가 보완할 경로를 기본 설계에 포함한다.
