# 사진별 카메라를 사용하는 보정

2026-10-15 구현·검증 기록. 승인된 설계는 `designs/camera-aware-reconstruction.md`에 보존했다. 남은 구현 선택은 사용자의 “추천하는 방향으로 선택” 지시에 따라 처리했다.

공통 카메라, 자동 정렬과 수동 보완, 보호 조건, 실측 옵션을 연결했다. **실제 사진을 이용한 복원 품질 검증까지 완료한 상태는 아니다.** 아래의 실행 근거와 남은 검증을 구분해서 사용한다.

## 사용 순서

```powershell
npm install
npm run cad:install
npm run cad:build
node src/cli.ts serve --dir <사진-작업-폴더> --port 5173
```

1. `front/back/left/right/top` 사진 5장을 준비한다. `사진 전체 관리`에서 업로드·교체·회전·반전·크롭을 조정한다.
2. 실제 촬영각이 다르면 입력 종류를 `실제 사진·각도 불일치 사진`으로 선택한다.
3. GLB/OBJ 초기 모델을 가져온다. `선택한 기준 사진으로 초기 모델 생성`은 기존 공급자를 호출하는 경로이며, 단일 사진 체크포인트의 실사용 지원은 아직 확인하지 못했다. 실패하면 오류가 표시되고 사진 교집합으로 대체하지 않는다.
4. `사진 전체 자동 정렬`을 실행한다. 확인이 필요한 사진은 크게 보고 사진 점 → 초기 모델의 같은 점 → 한 쌍 확인으로 보완한다. 수동 회전·위치·초점거리·투영 방식, 카메라 잠금, 사진 제외/복원을 사용할 수 있다. 기준점 변경 후에는 다시 검증한다.
5. 손잡이가 있다면 위·아래 연결 영역 → 실제 표면 경로 → 연결 확인을 진행한다. 구멍은 경계점 → 명시적인 경계 닫기 → 관통 시점에서 `이 방향 사용` → 전체 확인으로 등록한다. 경로·경계의 개별 점을 다시 선택하거나 삭제할 수 있다. 보호가 필요 없는 물체는 그 사실을 명시적으로 확인한다.
6. 필요하면 치수 구간의 두 점과 실측 mm 값을 한 항목씩 확인해 등록한다. 여러 값이 충돌하면 잔차를 확인한다.
7. `사진 보정 결과 만들기`를 실행하고 결과 상태·이유를 확인한다. 저장된 결과와 현재 화면에 표시하는 초기 모델/결과 모델은 구분해서 표시한다.

방향키로 사진·모델 커서를 이동하고 Enter로 후보를 고를 수 있다. Enter만으로 기준점 쌍이나 치수가 등록되지는 않는다. 선택 중 자동 회전은 멈추고 Tab으로 선택 영역을 나갈 수 있다. 관찰 모드의 방향키는 시점을 조절하며 +/−로 확대·축소한다.

## 결과 상태와 크기

| 상태 | 의미 |
|---|---|
| `reference` | 기존 정투영 참조 파이프라인 결과 |
| `accepted` | 현재 관측과 보호 검사를 통과한 제한적 형상 보정 |
| `initial-only` | 보호 선택 또는 관측이 부족해 초기 형상을 유지 |
| `rollback` | 보정 후 보호 또는 재투영 검사를 통과하지 못해 초기 형상으로 복귀 |

이 상태들은 실제 물체와 동일하다는 인증이 아니다. 사진 모드에서는 임의 각도 사진의 실루엣 교집합이나 전체 X축 대칭으로 초기 형상을 대체하지 않는다. 제품 프리셋도 대칭을 기본으로 끄고 명시적인 옵션으로 남겼다.

치수를 입력하지 않으면 상대 크기다. 치수가 있으면 형상을 균일하게 확대·축소하며 GLB는 m, OBJ는 mm로 저장한다. 여러 구간은 하나의 배율을 최소제곱으로 맞추고 각 잔차를 제공한다. 축마다 따로 늘려 숫자를 강제로 맞추지 않는다. `measurements.json`에서 적용 배율과 잔차를 확인할 수 있다.

## 데이터·코드 계약

| 파일 | 책임 |
|---|---|
| `src/render/camera.ts` | 물리 카메라·이미지 변환·공통 투영 |
| `src/reconstruct/camera-fit.ts` | 고정 초기 모델에 대한 유한 자세 탐색과 신뢰도 |
| `src/reconstruct/protection.ts` | 실제 표면 영역·경로·두께·구멍 검사와 제한적 보정/복귀 |
| `src/mesh/measurements.ts` | 실측 배율·잔차·GLB/OBJ 단위 |
| `cad/src/viewer/model-viewer.ts` | 스튜디오·독립 뷰어의 공통 표시와 canonical 선택 |

- 월드는 +X 오른쪽, +Y 위, +Z 앞이다. 물리 카메라는 +X 오른쪽, +Y 아래, +Z 앞이다. 이미지 반전은 이미지 변환으로 처리하며 물리 회전은 determinant +1을 검증한다.
- EXIF 방향 적용 후 원본 픽셀에서 prepared 픽셀까지의 변환을 기록한다. 형상 보정·색 투영·재투영은 같은 카메라를 사용한다. 관찰용 뷰어 변환은 따로 유지한다.
- `views.json`의 기존 이미지 변환과 `_reconstruction.version=2`를 함께 저장한다. 원본/이미지 변환이 바뀌면 정렬·기준점·보호·치수를 해제하고 검토를 요구한다. 초기 모델을 교체하면 그 모델에 연결된 입력도 초기화한다.
- 초기 형상은 `initial.glb`, 가져오거나 생성한 원본은 `initial-source.glb` 또는 `.obj`, 출처는 `initial-source.json`에 저장한다. 공급자 이름·모델·선택 사진·파일 해시를 기록하며 단일 사진 품질은 미검증으로 표시한다.
- 최종 `model-manifest.json`은 원본 해시, 카메라/보호/치수 기록 해시, 실제 GLB 해시를 연결해 마지막에 저장한다. 오래된 GLB가 남아 있어도 현재 결과로 나열하거나 내려주지 않는다. 이전 기록이 없는 모델은 초기 모델 가져오기로 다시 확인한다. CLI에서 별도 출력 폴더를 지정한 GLB/OBJ는 직접 사용할 수 있으며, 현재 입력에 묶인 웹 작업은 입력·상태가 있는 작업 폴더에서 연다.
- API는 `/api/initial`, `/api/initial/generate`, `/api/camera/fit`, `/api/reconstruction`, `/api/reconstruction/reset`, `/api/reprojection/:view`를 제공한다. 보정 요청의 source/mesh identity와, 스튜디오가 보내는 `X-Sixview-Revision`을 검사한다. 대기 중 오래된 변경은 409로 거절하고 다시 불러오도록 안내한다.
- 손상된 보정 파일은 경고 후 `보정 정보 백업 후 초기화`로 복구할 수 있다. 이전 파일을 `views.backup-<timestamp>.json`으로 보존한다.
- 연결 영역은 단일 점으로 승인하지 않으며 면적 있는 표면 샘플을 요구한다. 경로는 중간 표면 지지, 구멍은 닫힌 경계와 저장된 정규화 방향의 실제 관통을 검사한다. 표면 브러시는 보이는 표면에만 입력하고 표시 패치를 삼각형에 잘라 깊이 검사를 적용한다.

정렬은 최대 187회 평가하는 제한된 탐색이다. 현재 정렬 완료 기준은 IoU 0.85 이상, 기준점 RMS가 이미지 대각선의 1.5% 이내, 다른 방향 후보의 모호성 없음이다. 모호한 사진은 신뢰도를 낮추고 수동 기준점을 요구한다. 형상 보정은 신뢰도 0.65 이상의 서로 다른 관측이 두 방향 이상 있어야 하며, 세 번의 작은 변위와 변위 스무딩 후 보호·재투영을 다시 검사한다. 이 수치는 실제 촬영 데이터로 교정한 정확도 보장이 아니다.

## 실행한 검증

- `npm test`: **25/25 통과**. 기존 15개 검사와 카메라·상태·보호·치수·실제 HTTP 경계 10개 검사. 추가 자세 검사 하나에는 yaw/pitch/roll 각각 ±5/10/15도, 총 18개 조합이 포함된다. 대칭 물체에서 중복 기준점으로 방향 모호성이 해소됐다고 오인하지 않는 검사도 포함한다.
- `npm run typecheck`, `npm run build`, `npm run cad:build` 통과. CAD 빌드의 기존 OpenCascade `node:module` 외부화 경고는 남아 있다.
- 200mm fixture를 GLB에서 0.2m, OBJ에서 200mm로 재독출했다. 충돌 치수의 잔차, 잘못된 값, 원본/모델 identity 불일치, 위조된 신뢰도, 잘못된 보호, 오래된 다운로드·비동기 변경, 손상 파일 백업 복구를 검사했다.
- `stanley_xyz_aligned`의 실제 5개 파일을 기준 커밋 `7fa9f58`과 새 정투영 코드로 두 번씩 교대로 처리했다. 해상도 96에서 위치·인덱스·색 데이터가 모두 같고 48,136개 삼각형, IoU 0.9827078736, 색 일치도 0.9540692990으로 일치했다. 원본 해시도 유지됐다. 이 사진은 AI 정투영 참조 회귀이며 실제 촬영각 복원 정확도 검사가 아니다.
- 위 회귀 실행 시간은 기준 1.13/1.57초, 현재 1.14/2.27초였다. 표본이 작고 변동이 있어 성능 동등성을 주장하지 않는다. 별도의 48,136 삼각형 합성 투영 한 장 자세 탐색은 187회, 약 1.27초였다. 공간 검색과 픽 선택 캐시의 소유·크기 제한을 코드에 적용했다.
- 실제 빌드/HTTP 서버에서 키보드 기준점 한 쌍 저장, 브러시 단계 이동, 치수 두 끝점·200mm 등록, 초기 형상만 제공하는 생성, 결과/초기 모델 전환을 확인했다. 독립 뷰어의 상태·이유, 모델 전환, front 프리셋, wireframe, 없는 복셀 버튼 비활성화와 해당 여정의 콘솔 error 0건을 확인했다. GPU 셰이더 정밀도 경고는 관찰됐다.
- 375/768/1440px DOM 배치와 123.45 입력값 유지, 375px에서 새 작업 버튼/입력의 최소 44×44px, 로컬 Pretendard 로딩을 확인했다. 사진과 모델의 선택 중 회전 정지 및 키보드 선택도 확인했다.

기계 판독 근거와 테스트 출력은 `evidence/camera-reference-evidence.json`, `evidence/camera-fit-runtime.json`, `evidence/camera-tests.txt`에 보존한다. `evidence/camera-font-http.json`은 실제 서버에서 글꼴 2개와 라이선스 파일을 HTTP 200으로 확인한 기록이다. 브라우저 이미지 `evidence/camera-studio.jpg`는 합성 비대칭 손잡이 fixture이며 Stanley 결과로 해석하지 않는다.

## 남은 승인 기준

다음 항목은 구현된 경로의 별도 실사용 검증으로 남아 있다. 이 항목들을 통과하기 전에는 CT8 전체 완료, 실제 사진 품질 보장 또는 출하 준비 완료로 표시하지 않는다.

- 로컬 AI venv·체크포인트가 현재 작업공간에 없다. 실제 단일 사진 추론 및 사용 가능한 초기 형상인지에 대한 CP7 검증을 하지 못했다. 원격 공급자의 읽기 전용 설정 조회는 HTTP 200이고 `shape_generation` API가 존재했지만, 이것은 추론 성공 근거가 아니다. Stanley 정면 사진을 Hugging Face Hunyuan 서비스에 전송하는 실행은 자동 승인 검토에서 해당 목적지로의 명시적 전송 승인 부재를 이유로 차단됐다. 사진 업로드와 추론은 실행되지 않았다. `evidence/camera-provider-preflight.json`과 `evidence/camera-provider-live.json`에 구분해 기록했다. 사용자 승인 전에는 이 검증을 실행하지 않는다.
- 측정된 실제 촬영 사진 세트의 pose/손잡이/구멍/로고·실측 정확도와 형상 품질 검증.
- 실제 화면 낭독기, OS의 동작 줄이기 전환, 200% 브라우저 확대, 글꼴 응답 실패 시 사용성.
- 느린/실패하는 모델 응답을 강제한 브라우저 수명주기 검사, 반복 전환의 GPU 리소스 측정, 큰 메시의 보호 선택·반복 편집 성능. 일반적인 전환은 확인했으나 모든 실패 상황을 검증한 것은 아니다.

현재 작업은 로컬 변경으로 보존한다. 기존 승인 문서의 검토 당시 상태와 결과를 소급해서 통과로 바꾸지 않는다.
