# 던전 원정 — office-hours 설계 기록

2026-10-16 · Builder mode · 선택 위임에 따라 구현 방향 확정

## 문제와 재미의 중심

사용자는 “내가 만든 포켓몬을 오픈월드에서 수집하고 탐험하는 게임”에 “던전도 만들고 실제 게임 레퍼런스 찾아서 디벨롭”을 요청했다. 지금 섬에는 이동과 포획은 있지만, 준비한 파트너로 목표를 달성하고 보상을 들고 돌아오는 짧은 모험이 없다.

핵심은 내가 꾸민 3D 포켓몬이 던전의 주인공이 되고, 방을 통과하며 강화 방향을 고르고, 마지막 수호자를 새 친구로 데려오는 장면이다. 수집한 친구를 다시 제작 화면에서 꾸밀 수 있어 제작 → 모험 → 수집 → 제작이 이어진다.

## 확인한 실제 게임 레퍼런스

공식 소개·개발자 문서의 구조만 참고하며 원작 이미지·맵·음원을 가져오지 않는다.

| 게임과 출처 | 확인한 원리 | 이번 구현에 적용 |
| --- | --- | --- |
| [포켓몬 불가사의 던전 구조대 DX](https://mysterydungeon.pokemon.com/en-us/world/) | 파트너와 구조 임무를 수행하고 다양한 포켓몬을 동료로 맞이한다. 동료의 기술에 따라 던전 공략이 달라진다. | 직접 만든 파트너로 출발, 속성 기술, 최초 클리어 수호자 도감 등록·동료 선택 |
| [Minecraft Dungeons](https://www.minecraft.net/en-us/about-dungeons) | 던전 전투·보물 미션·아이템 수집을 묶은 액션 어드벤처 | 입구, 각 방의 적, 열리는 문, 마지막 보상으로 읽히는 짧은 탐험 동선 |
| [Hades 개발자 패치 노트](https://www.supergiantgames.com/blog/hades-welcome-to-hell-update-patch-notes/) | 축복 선택과 출구의 방 보상 미리보기 | 방마다 공격·생존·방어 강화 중 선택. 원정 안에서만 적용되고 다음 방 목표를 미리 표시 |

위의 시스템을 그대로 재현한다는 뜻은 아니다. 턴 전투와 세 방 구성은 현재 웹 프로젝트의 조작성·규모에 맞춰 내린 설계 결정이다.

## 전제와 대안

- 던전 수 자체보다 입장 → 탐색 → 전투 → 강화 → 수호자 → 귀환의 완결성이 우선이다.
- 현재의 제작·섬 저장을 유지하고, 던전 좌표가 섬 좌표에 섞이지 않아야 한다.
- 처음 해도 공격 예고와 조작을 이해할 수 있어야 한다. 실시간 조작 숙련보다 선택이 중요하므로 전투는 턴 방식으로 만든다.

| 대안 | 이점 | 비용·위험 | 결정 |
| --- | --- | --- | --- |
| 섬의 제단에서 전투 창만 열기 | 가장 적은 변경, 빠른 연결 | 실제 던전을 탐험하는 느낌이 약함 | 채택하지 않음 |
| 별도 3D 던전 장면 + 순수 전투 규칙 | 실제 공간, 세 테마 확장, 저장과 검증 분리 | 장면·UI 수명 관리 필요 | 채택 |
| 매번 생성되는 실시간 로그라이크 | 긴 반복 플레이, 조합의 다양성 | 경로·충돌·전투 밸런스 검증 범위가 크게 증가 | 이번 범위에서 제외 |

선택은 이전의 “선택해야 하는건 너가 대신 선택해줘” 지시에 따른다. 이번 요청은 구현까지 포함하므로 office-hours의 설계 작업을 마친 뒤 개발을 이어간다.

## 구현할 플레이

세 던전: 이끼빛 성소(입문), 잿불 공방(보통), 달그림자 유적(도전). 각 던전은 연결된 세 방이며 색상·적 구성·난이도·수호자 보상이 다르다.

1. 원정 로비에서 테마·난이도·최초 보상과 현재 파트너를 확인한다.
2. 3D 공간을 WASD/방향키 또는 모바일 패드로 이동한다. 가까운 적에게 E로 도전한다.
3. 공격, 속성 기술, 방어, 회복 중 하나를 선택한다. 적의 다음 행동과 피해량이 표시된다. 행동할 때만 전투 시간이 흐른다.
4. 방 1·2를 클리어하면 강화 하나를 골라 다음 문으로 이동한다. 중복 강화는 제한하고 체력·자원은 같은 원정 내에서 유지한다.
5. 마지막 수호자 승리 후 최초 보상과 도감 친구를 받는다. 재도전은 가능하되 최초 보상은 반복 지급하지 않는다.
6. 쓰러지거나 중도 귀환해도 기존 컬렉션·탐험 진행은 잃지 않는다. 진행 중 원정은 새로고침 또는 만들기·컬렉션 이동 시 초기화된다. 출발 전에 이 점을 표시한다.

## 구조와 저장 계약

- dungeon-data.js: 정적 테마·적, 불변 전투/강화/진행 reducer. 외부 의존성 추가 없음.
- dungeon-scene.js: 별도 Three.js renderer. 기존 buildCreature 재사용, 낮은 벽으로 시야 확보, 문 잠금과 방 이동.
- dungeon-ui.js / dungeon.css: 로비, HUD, 전투 패널, 강화, 결과, 키보드·터치 입력.
- world-ui.js: 원정 열기·닫기, 기존 renderer/키보드 중지, 달의 제단 연결, 도감·경험치 동기화.
- world-data.js: 기존 v1 저장에 dungeons.cleared 기본값 추가. 고정 수호자 ID 허용. 최초 보상·도감 등록은 하나의 상태 변경으로 처리.
- 도감 정원 부족 시 최초 보상을 소비하지 않고 이유를 표시한다. 실패·중단·중복 클릭으로 보상을 지급하지 않는다.
- 다른 탭에서 월드 저장이 바뀌면 원정을 종료하고 최신 저장을 채택한다. 원정 상태가 기존 저장을 덮어쓰지 않는다.

## 완료 기준

- 기존 저장으로 실행해 제작·컬렉션·섬 위치가 유지된다.
- 세 던전 모두 진입, 방 이동, 전투, 강화, 수호자, 결과, 재입장이 가능하다.
- 무효 행동은 턴/자원을 소비하지 않는다. 보상 중복, 잠긴 방 건너뛰기, 쓰러진 뒤 공격이 차단된다.
- 최초 보상 수호자가 도감·파트너 목록에 남고 새로고침 후 복원된다.
- 실제 브라우저에서 한 원정을 끝까지 플레이하고 좁은 화면 배치도 확인한다.
- Node 테스트 및 Vite 프로덕션 빌드가 통과한다.

## 전달과 다음 체험

현재 로컬 웹 서버에서 실행하고, 소스·테스트·설계·빌드 결과를 프로젝트 ZIP에 포함한다. 외부 업로드·배포는 이번 범위에 포함하지 않는다.

완성 후 이끼빛 성소에 직접 만든 친구를 데려가 첫 방의 공격 예고를 읽고 방어를 한 번 사용해본다. 이후 다른 강화로 재도전해 선택이 전투를 바꾸는지 비교한다.

## 작업 맥락과 한계

“만든 포켓몬” → “오픈월드” → “던전” 순서로 요청이 이어졌다. 이번 확장도 제작한 캐릭터가 플레이의 중심에 남도록 설계한다. 고객 수요나 사업 가설은 이번 대화에서 확인하지 않았고 상업적 성공을 가정하지 않는다.

office-hours 보조 스크립트는 Windows 샌드박스에서 MSYS 초기화 오류로 실행되지 않았다. 자동 프로필·외부 기록·정형 리뷰 helper는 실행하지 않았으며 프로젝트 내부 설계 기록과 코드 검증으로 진행한다. 설치 복구는 gstack의 ./setup 또는 /gstack-upgrade에서 별도로 할 수 있다.

별도 에이전트의 설계 검토에서 구현을 막는 공백은 발견되지 않았다. 통합 코드 검토에서 지적한 다른 화면 이동 시 원정 종료 동작은 출발 안내와 README에 명시했다. 자동 리뷰 helper의 정형 점수나 외부 모델 검증을 받은 것은 아니다.

재사용할 교훈: 같은 캔버스 좌표를 월드·던전 저장에 공유하면 섬 위치가 던전 좌표로 덮인다. 임시 원정의 장면과 입력 수명을 분리하고, 완료 보상만 검증된 월드 상태로 전달한다.
